# 0021 — Setlist song limit and language-dependent voice playlists

## Status

Accepted

## Date

2026-10-24

## Context

Setlists were unbounded, which could cause performance issues and UX problems. Also, the voice playlist UI was confusing: it showed a mix of original-language audio (Spotify/YouTube) and translated-language Navidrome shares in the same view, and the active voice section was shared between the song list and the voice playlists panel.

## Decision

### 1. Setlist song limit (commit a17b484)

Add a configurable maximum number of songs per setlist (default 50, configurable via `SETLIST_MAX_SONGS` env var):

- Validation in API routes (`POST/PUT /api/setlists`) — returns 400 if exceeded
- Client-side enforcement in `SetlistEditor` — disables search input, shows warning
- Limit displayed as "Songs (X / 50)" in the editor header
- Uses new `getSetlistMaxSongs()` config function in `src/lib/config.ts`

### 2. Language-dependent voice playlists (commits 4db2eb9, f93f8ab, 7985931, ff85179)

Redesign voice playlist UI in `SetlistReadOnlyView` and `SetlistVoicePlaylists`:

- **Original language songs**: Show Spotify/YouTube embeds (if URLs exist in song metadata)
- **Translated language songs**: Show Navidrome per-voice shares instead (no Spotify/YouTube)
- **ALL tab**: Lists all songs with appropriate audio source per language
- **Per-section tabs**: Show Navidrome iframe for the active voice section only
- **SongVoiceSelector component**: New component for selecting voice part (gender + section) per song
- **Preferred voice**: Uses user's profile `voice` preference for initial selection, then internal state
- **Removed**: Language selector from read-only view (language is pinned per setlist item)

### 3. Audio embedding for songs (commit 4db2eb9)

- Added `spotify`, `youtube`, `originalLang` fields to setlist song data
- `SongAudioEmbed` component handles lazy-loaded iframes for Spotify/YouTube/Navidrome
- Spotify/YouTube URLs parsed to extract track/video IDs for embed URLs
- IntersectionObserver for lazy loading off-screen embeds

## Consequences

### Positive

- Prevents excessively long setlists
- Clear separation: original language = commercial audio, translations = practice recordings
- Per-song voice selector lets singers pick their part independently
- User's preferred voice pre-selected but not forced
- Lazy loading improves initial page load

### Negative

- More complex voice playlist UI with multiple tab layers (ALL / gender / section)
- Translated languages don't show commercial audio even if available
- `SETLIST_MAX_SONGS` requires container rebuild to change (env var only)
- Voice shares must be generated by setlist owner; no auto-regeneration on song change

### Carried forward

- `SETLIST_MAX_SONGS` env var in `docker-compose.yml` and `.env.example`
- `getSetlistMaxSongs()` in `src/lib/config.ts`
- `SongVoiceSelector` component (uncontrolled, uses `preferredVoice` for initial state)
- `SongAudioEmbed` component with lazy loading
- `SetlistVoicePlaylists` always uncontrolled internally; `preferredVoice` for initial tab
- Language filter removed from `SetlistReadOnlyView` props
